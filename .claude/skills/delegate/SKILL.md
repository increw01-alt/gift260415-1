# /delegate — Codex 에 위임

목표: Codex 가 **추가 질문 없이** 끝까지 할 수 있는 지시문을 만든다.

## 1. 지시문 쓰기 전에

1. `project.yaml`, 관련 기획서(`production/briefs/`), 대상 파일을 읽는다.
2. 재욱님의 지시가 애매하면 **지시문을 쓰기 전에** 먼저 묻는다. 추측으로 지시문을 채우지 않는다.
   단, 색상·문구·파일명 같은 사소한 것은 묻지 않고 정한다.
3. 작업 브랜치를 정한다. 배포 브랜치에서 작업시키지 않는다.

## 2. 지시문 작성

`.claude/docs/templates/codex-task.md` 형식을 그대로 쓴다. 빠뜨리면 안 되는 것:

- **대상 파일**: 실제 경로. 존재하지 않는 경로를 지어내지 않는다 (Glob 으로 확인한다)
- **유지할 것**: 기존 기능, 분석·광고 코드, 기존 URL
- **금지 사항**: push·배포·삭제, 다른 브랜드 자산, 근거 없는 수치
- **검수 기준**: 팀장이 실제로 실행할 명령과 통과 조건
- **완료 조건**: 예/아니오로 판정할 수 있는 문장

`production/tasks/YYYY-MM-DD-<짧은-이름>.md` 로 저장하고,
재욱님이 Codex 에 바로 붙여 넣을 수 있게 **지시문 전체를 코드 블록으로** 보여 준다.

## 3. 결과를 받았을 때

Codex 의 완료 보고를 그대로 믿지 않는다. 순서대로 확인한다.

1. `git log --oneline -5`, `git diff --stat <작업 시작 지점>` — 실제로 무엇이 바뀌었는가
2. 변경이 지시한 범위 안에 있는가. 범위 밖 파일이 바뀌었으면 표시한다
3. `python3 .claude/scripts/site-check.py` — 오류 0건인가
4. 지시문의 검수 기준과 완료 조건을 하나씩 대조한다
5. 분석 코드, 기존 기능, 기존 URL 이 그대로인가
6. 강도가 `standard` 이상이면 `/review`

## 4. 재욱님에게 보고

```
## 위임 결과 — [작업명]
판정: 통과 | 수정 필요 | 반려
확인한 것: (실행한 명령과 결과)
Codex 보고와 다른 점: (있으면)
남은 일: 
확인 대기: (push·배포 등 재욱님 승인이 필요한 것)
```

수정이 필요하면 **무엇이 어느 파일 몇 번째 줄에서 왜 틀렸는지**를 적은 후속 지시문을 만든다.
같은 문제로 두 번 반려되면 지시문이 모호했던 것이므로 지시문부터 고친다.
