# /handoff — 체크포인트 갱신

목표: 처음 보는 세션이 **이 파일만 읽고** 바로 이어서 일할 수 있게 한다.

## 순서

1. 현재 상태를 실제로 확인한다. 기억으로 쓰지 않는다.
   - `git rev-parse --abbrev-ref HEAD`, `git status --short`, `git log --oneline -5`
2. `production/session-state/active.md` 를 연다. 없으면
   `.claude/docs/templates/session-state.md` 를 복사해 만든다.
3. `<!-- CHECKPOINT -->` 와 `<!-- /CHECKPOINT -->` 사이를 **덮어쓴다** (덧붙이지 않는다, 25줄 이내).
   두 표시 줄 자체는 지우지 않는다. 세션 시작 훅이 이 구역을 읽는다.

   | 항목 | 쓰는 법 |
   |---|---|
   | 갱신 | 지금 날짜와 시각 |
   | 브랜치 | 실제 브랜치명 |
   | 지금 하는 일 | 한 줄 |
   | 다음 한 걸음 | 파일명과 동작이 들어간 한 줄. "계속 진행" 같은 말은 쓰지 않는다 |
   | 막힌 것 | 없으면 "없음" |
   | 작업 중 파일 | 커밋 안 된 파일 |
   | 확인 대기(재욱님) | push·배포·삭제 등 승인을 기다리는 것 |

4. 그 아래 "기록" 구역에 오늘 한 일을 2~4줄로 **덧붙인다**. 결정한 것과 그 이유를 남긴다.
5. 저장소에 `PROGRESS.md` 나 `HANDOFF.md` 가 있으면 완료·대기·다음 순서를 같이 갱신한다.
   없고, 작업이 여러 날 걸리는 것이면 `PROGRESS.md` 를 만든다.
6. 기록 구역이 200줄을 넘으면 오래된 부분을 `production/session-logs/` 의 날짜 파일로 옮기자고 제안한다.
   (지우지 않고 옮긴다)

## 보고

갱신한 체크포인트를 그대로 한 번 보여 주고 끝낸다. 길게 설명하지 않는다.
