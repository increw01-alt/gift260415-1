# /brief — 1장 기획서

목표: 만들기 전에 **한 장**으로 목적·구성·완료 조건을 정한다. 한 장을 넘기지 않는다.

## 순서

1. `project.yaml` 을 읽는다. `modes.rigor` 가 `minimal` 이고 작업이 작으면
   "이 작업은 기획서 없이 바로 진행해도 됩니다"라고 알리고 재욱님이 원할 때만 계속한다.
2. 관련 기존 파일을 읽는다 (비슷한 페이지, 디자인 토큰, 기존 컴포넌트, 기존 CTA 문구).
   이미 있는 것을 새로 만들지 않기 위해서다.
3. `.claude/docs/templates/brief.md` 형식으로 초안을 쓴다.
   - 비어 있는 정보는 업종·목적·기존 페이지를 기준으로 합리적인 값을 정해 채우고, 가정은 8번 항목에 적는다.
   - 색상·문구·레이아웃 같은 사소한 선택은 묻지 않는다.
   - 수치·후기·인증처럼 확인이 필요한 사실은 지어내지 않고 플레이스홀더로 둔다.
4. `production/briefs/YYYY-MM-DD-<짧은-이름>.md` 로 저장한다.
5. 재욱님에게 보여 줄 때는 전체를 다시 붙이지 말고 **구성(4번)과 완료 조건(7번), 가정(8번)** 만 요약한다.
6. 방향이 크게 갈리는 결정이 있을 때만 선택지 2~3개와 추천안을 제시한다. 없으면 바로 다음 단계로 간다.

## 다음 단계

- 구현을 Codex 에 넘길 때: `/delegate`
- 팀장이 직접 만들 때: 기획서의 완료 조건을 체크리스트로 삼아 진행한다
- 강도 `full` (이전·리뉴얼): 기획서에 더해 **기존 URL 목록과 리다이렉트 표**를
  `production/briefs/` 에 따로 만든다. 기존 게시글과 URL 은 보존이 원칙이다.
