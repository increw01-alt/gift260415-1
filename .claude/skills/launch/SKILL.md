# /launch — 배포 전 최종 점검

배포 브랜치 push 는 곧 실제 배포다. 이 명령은 **점검하고 승인을 요청하는 데까지**만 한다.
push 는 재욱님이 승인한 뒤에 한다 (승인 창은 훅과 권한 규칙이 강제로 띄운다).

## 1. 점검

순서대로 실행하고 결과를 기록한다. 실행하지 못한 항목은 "확인 못 함"으로 적는다.

1. **상태**: `git status --short` (커밋 안 된 변경), 현재 브랜치, 배포 브랜치와의 차이 `git log --oneline <배포 브랜치>..HEAD`
2. **정적 점검**: `python3 .claude/scripts/site-check.py --strict` — 오류 0건이어야 한다
3. **빌드**: `project.yaml` 의 `site.build_command` 가 있으면 실행. 출력 폴더가 `site.output_dir` 과 맞는가
4. **임시값**: 점검 결과의 플레이스홀더 목록(`GTM-XXXXXXX`, `TODO` 등). 배포해도 되는 것과 안 되는 것을 구분한다
5. **분석 코드**: 배포 브랜치와 비교해 GTM·GA4·Ads·Pixel·Naver Analytics 코드가 빠지지 않았는가
   `git diff <배포 브랜치>...HEAD | grep -E '^-.*(GTM-|gtag|fbq|wcs)'`
6. **브랜드**: 점검 결과의 다른 브랜드 도메인·번호 경고를 하나씩 판단했는가
7. **검색**: `sitemap.xml`, `robots.txt`, canonical 의 도메인이 `project.yaml` 과 일치하는가
8. **비밀정보**: 점검 결과에 비밀정보 오류가 없는가. `.env` 가 `.gitignore` 에 있는가
9. **검수**: 강도가 `standard` 이상이면 `/review` 를 했고 차단 항목이 남아 있지 않은가

`--migration` (사이트 이전·리뉴얼) 일 때 추가

10. 기존 URL 목록의 모든 주소가 새 사이트에서 열리거나 리다이렉트되는가 (`production/briefs/` 의 리다이렉트 표와 대조)
11. 기존 게시글·콘텐츠가 빠짐없이 옮겨졌는가 (개수 대조)
12. 원본 전체 백업이 어디에 있는가
13. 배포 후 할 일: 도메인 연결 확인, sitemap 재제출(구글 서치콘솔, 네이버 서치어드바이저)

## 2. 보고와 승인 요청

```
## 배포 전 점검 — [사이트명] → [배포 브랜치]
배포될 변경: 커밋 N개, 파일 N개
통과: (항목)
걸린 것: (항목 — 내용 — 조치 또는 사유)
확인 못 함: (항목과 이유)
배포 후 확인 방법: (열어 볼 주소, 확인할 것)

배포해도 될까요?
```

- 걸린 것 중 오류는 **먼저 고치고** 다시 점검한 뒤 승인을 요청한다.
- 승인을 받으면 일반 push 만 한다. 강제 push 는 하지 않는다.
- 배포 뒤에는 `/handoff` 로 체크포인트를 갱신하고, 재욱님이 확인할 주소를 알린다.
  배포 결과를 직접 확인하지 못했으면 확인했다고 쓰지 않는다.
