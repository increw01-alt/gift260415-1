# 작업 강도 3단계

`project.yaml` 의 `modes.rigor` 가 기본값이다. 작업 하나만 다르게 하고 싶으면
재욱님이 말로 지정한다 (예: "이건 full 로").

| 강도 | 어떤 작업 | 시작 전 문서 | 끝난 뒤 검수 |
|---|---|---|---|
| `minimal` (기본) | 문구·스타일 수정, 단일 페이지 보완, 버그 수정 | 없음 | `/site-check` |
| `standard` | 신규 랜딩·신규 사이트, 섹션 재구성, 자동화 스크립트 신규 | 1장 기획서 (`/brief`) | `/site-check` + `/review` (관련 검수자만) |
| `full` | 사이트 이전·리뉴얼, URL 구조 변경, 도메인 연결 | 1장 기획서 + 기존 URL 목록과 리다이렉트 표 | `/review` (5명 전원) + `/launch` |

원칙

1. **문서를 늘린다고 결과가 좋아지지 않는다.** 기획서는 한 장을 넘기지 않는다.
   더 쓰고 싶어지면 그 시간에 만들어서 확인한다.
2. 강도는 "얼마나 조심할지"이지 "얼마나 많이 쓸지"가 아니다.
   `full` 에서 늘어나는 것은 문서가 아니라 확인 항목(기존 URL 보존, 리다이렉트, sitemap 재제출)이다.
3. 강도와 무관하게 항상 지키는 것: 브랜드 분리, 비밀정보 금지, 배포 전 재욱님 확인.
4. 애매하면 낮은 강도로 시작하고, 범위가 커지면 올린다.
