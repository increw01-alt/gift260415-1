# Codex 작업 지시문 — 3. 정적 페이지 초안 8개, 문의 폼, FAQ, sitemap·robots·404

작성: 2026-11-17 / 작성자: 팀장(Claude Code)

## 목적
방문자가 전화·카카오톡·문의 폼 중 하나로 쉽게 문의하도록 8개 페이지의 **초안**을 만든다. 문구와 디자인의 최종 판단, 통합은 팀장이 한다. 초안은 구조와 내용이 빠짐없이 들어가는 것이 우선이다.

## 현재 상황
`src/pages/index.html` 은 빌드 확인용 자리 페이지다. 공통 조각(`src/partials/`: head, header, footer, floating, bottombar)과 `public/js/common.js`(모바일 메뉴, 문의 유형 미리 선택, CTA dataLayer) 는 완성되어 있으므로 **수정하지 않는다**. 검증 함수 `functions/lib/validate.js` 는 빌드 때 `public/js/validate.js` 로 복사되며 브라우저에서 `import` 할 수 있다. API 는 `POST /api/inquiry` (JSON) 이고 응답은 `docs/design.md` 3절과 같다.

## 문구 규칙 (가장 중요)
- 한국어, 정중한 문어체("~합니다", "~해 주세요"). 이모지·느낌표 남발 금지.
- **쓰지 않는 말**: 협회, 공식, 인증, 승인, 제휴, 기관, 현금화, 현금 환전, 수수료 없음, 100%, 즉시 한도, 누구나 가능, 보장, 최저가, 업계 최고. 근거 없는 숫자(이용자 수, 건수, 만족도), 후기, 수상 금지.
- 수집하지 않는 것을 말할 때도 "인증" 을 피한다: "휴대폰으로 받은 확인 번호, 카드·계좌 번호, 주민등록번호는 묻지 않습니다".
- 이 사이트는 **상품권 구입 문의·안내** 서비스다. 상품권을 되팔거나 현금으로 바꾸는 내용은 어디에도 쓰지 않는다.
- 취급 상품권·금액·환불 규정처럼 사업 조건은 단정하지 않는다: "문의 시 안내합니다", 또는 `[확인 필요: 환불 규정]` 플레이스홀더.
- 브랜드 값은 `{{site_name}}`, `{{phone}}`, `{{hours}}`, `{{kakao_url}}` 치환자를 쓴다. 번호·주소를 직접 적지 않는다.
- 휴대폰결제·소액결제 관련 버튼은 **반드시** `/contact/?type=mobile-payment` 또는 `/contact/?type=micro-payment` 로 보내고 `data-cta="<페이지>_<위치>"` 를 붙인다. 전화 버튼은 `href="tel:{{phone}}"`, 카카오톡은 `href="{{kakao_url}}" target="_blank" rel="noopener"`.
- 페이지마다 H1 하나, H2→H3 순서로 단계를 건너뛰지 않는다. 이미지는 넣지 않고 `<div class="aspect-[16/9] rounded-xl bg-surface" role="img" aria-label="(이미지 자리) …">` 로 자리만 둔다.

## 페이지별 구성과 핵심 내용
### `/` 메인 (`index.html`)
1. Hero: H1 "휴대폰결제·소액결제로 상품권 구입, 먼저 문의하세요" (뜻이 같으면 다듬어도 됨). 보조문 2줄: 어떤 서비스인지, 문의하면 무엇을 안내받는지. 버튼 3개: 휴대폰결제 구입 문의(primary, type=mobile-payment), 소액결제 구입 문의(secondary, type=micro-payment), 전화 {{phone}}. 이미지 자리 1개.
2. "이런 분께 안내합니다" 카드 3개: 휴대폰결제로 상품권을 사고 싶은 분 / 소액결제 한도 안에서 구입하려는 분 / 어떤 상품권을 어떤 결제로 살 수 있는지 궁금한 분.
3. 이용 흐름 3단계: 문의 → 구입 가능 여부·결제 방법 안내 → 결제 후 상품권 수령. 각 단계 1~2문장.
4. 자주 묻는 질문 3개 (`<details>`): 어떤 상품권을 살 수 있나요 / 휴대폰결제와 소액결제는 무엇이 다른가요 / 문의하면 바로 답을 받을 수 있나요. 하단에 `/faq/` 링크.
5. 문의 유도 배너: 제목 + 전화·카카오톡·문의 폼 버튼 3개 + 상담시간 {{hours}}.

### `/guide/` 상품권 구입 안내
H1 "상품권 구입 안내". 섹션: (1) 구입 흐름 요약 (2) 상품권 종류별 안내 — 모바일 상품권(핀번호형), 기프트카드형, 온라인 전용 코드형: 각각 어떻게 받고 어디에 쓰는지 일반 설명. 특정 상품권 이름은 "예:" 수준으로 2~3개만. "취급 여부와 수량은 시기에 따라 달라 문의 시 안내합니다" (3) 결제수단별 안내 — 휴대폰결제, 소액결제, 그 밖의 결제수단은 문의 (4) 준비할 것 — 본인 명의 휴대폰, 통신사 한도 확인 방법(통신사 앱·고객센터), 받을 연락처 (5) 문의 CTA (type=voucher-type, 전화).

### `/mobile-payment/` 휴대폰결제·소액결제 구입 문의 안내
H1 "휴대폰결제·소액결제로 상품권 구입하기". 섹션: (1) 두 결제의 차이 — 휴대폰결제(통신사 소액결제): 통신요금에 합산 청구, 월 한도는 통신사·이용 기간에 따라 다름 / 소액결제: 같은 방식의 일반 명칭. 표 1개. (2) 진행 순서 4단계: 문의 → 한도·결제 가능 여부 확인 → 결제 → 상품권 전달. (3) 유의사항 목록: 본인 명의 휴대폰만, 통신요금 연체 시 이용 제한, 미성년자 이용 불가, 한도 변경은 통신사에서, 청구 시점. (4) 문의 CTA 2개 (type=mobile-payment / type=micro-payment) + 전화.

### `/faq/` 자주 묻는 질문
H1 "자주 묻는 질문". 4묶음(H2) × 각 3~4개 `<details><summary>`: 구입(어떤 상품권, 최소·최대 금액 → 문의 시 안내, 영업시간 외 문의) / 결제(휴대폰결제 한도 확인법, 통신요금 청구 시점, 결제 실패 원인) / 수령(어떻게 받나, 얼마나 걸리나, 못 받았을 때) / 취소·변경([확인 필요: 환불 규정] 플레이스홀더 포함, 잘못 입력한 연락처). 끝에 문의 CTA.

### `/how-to/` 이용 안내
H1 "이용 안내". 섹션: 문의 방법 3가지 비교표(전화·카카오톡·문의 폼: 가능 시간, 답변 방식, 이런 때 편리) / 문의부터 수령까지 전체 흐름 / 운영시간 {{hours}} 과 영업시간 외 접수 안내 / 안전한 이용을 위한 안내(묻지 않는 정보: 휴대폰으로 받은 확인 번호, 카드·계좌 번호, 주민등록번호 / {{site_name}} 이름으로 다른 번호에서 연락하지 않음).

### `/contact/` 문의하기
H1 "문의하기". 왼쪽(모바일은 위) 폼, 오른쪽(모바일은 아래) 전화·카카오톡 카드.
폼 `<form id="inquiry-form" method="post" action="/api/inquiry" novalidate>`:
- `select name="type"` 옵션 value: `mobile-payment` 휴대폰결제 구입, `micro-payment` 소액결제 구입, `voucher-type` 상품권 종류 문의, `other` 기타. 첫 옵션은 value="" "문의 유형을 선택해 주세요".
- `input name="name"` (이름 또는 닉네임, maxlength 30), `input name="contact" type="tel"` (휴대폰 번호 또는 카카오톡 ID, maxlength 40, autocomplete tel), `textarea name="message"` (문의 내용, maxlength 1000, placeholder 에 "주민등록번호·카드번호는 적지 말아 주세요").
- honeypot: `<div class="hidden" aria-hidden="true"><label>웹사이트<input name="website" tabindex="-1" autocomplete="off"></label></div>`
- `input type="hidden" name="page"` 는 JS 가 `location.pathname + location.search` 로 채운다.
- 동의: `<input type="checkbox" name="consent" id="consent" required>` + 라벨 "개인정보 수집·이용에 동의합니다. (수집 항목: 문의 유형, 이름 또는 닉네임, 연락처, 문의 내용 / 이용 목적: 문의 답변 / 보유 기간: 답변 완료 후 1년, [확인 필요: 보유 기간])" + `/privacy/` 링크. 제출 버튼은 동의 전 `disabled`.
- 각 필드 아래 `<p class="field-error" data-error-for="name"></p>` 식의 오류 자리, 폼 위에 `<div data-form-status role="status" aria-live="polite"></div>`.
- 제출 성공 시 폼을 숨기고 "문의가 접수되었습니다. {{hours}} 에 순서대로 연락드립니다. 급하시면 전화 {{phone}}" 메시지와 전화 버튼을 보여 준다.

### `public/js/contact.js` (`<script type="module" src="/js/contact.js">` 로 contact 페이지에서만 로드)
`import { validateInquiry, isHoneypotTripped } from "/js/validate.js"`. 동작: 동의 체크에 따라 제출 버튼 활성화 / submit 시 `validateInquiry` 로 먼저 검사해 항목별 오류를 `data-error-for` 에 표시하고 첫 오류 필드로 포커스 / 통과하면 `fetch("/api/inquiry", { method:"POST", headers:{"content-type":"application/json"}, body: JSON.stringify(data + page) })` / 응답 `ok` 면 성공 화면, 400 이면 서버 `errors` 를 같은 자리에 표시, 429·500 이면 `errors._` 를 상태 영역에 표시 / 전송 중 버튼 비활성·"보내는 중…" / 성공 시 `window.dataLayer.push({ event: "inquiry_submit", type })`.

### `/privacy/` 개인정보처리방침
H1 "개인정보처리방침". 한국 표준 구성: 수집 항목(폼과 동일 + 접속 기록·브라우저 정보)과 수집 방법 / 이용 목적(문의 답변, 서비스 안내) / 보유·이용 기간([확인 필요: 보유 기간]) / 제3자 제공 없음 / 처리 위탁(클라우드 호스팅·데이터 저장: Cloudflare, [확인 필요: 그 밖의 수탁자]) / 정보주체의 권리와 행사 방법 / 파기 절차 / 안전성 확보 조치 / 쿠키·분석 도구(Google 태그 관리자·애널리틱스 사용, 거부 방법) / 개인정보 보호책임자 [확인 필요: 성명·연락처] / 시행일 [확인 필요]. 각 조는 H2.

### `/terms/` 이용약관
H1 "이용약관". 목적·정의·약관의 효력과 변경·서비스의 내용(상품권 구입 문의·안내)·이용자의 의무(본인 명의 결제수단, 허위 정보 금지)·회사의 의무·면책·분쟁 해결·시행일 [확인 필요]. 각 조는 H2. 상호·주소 등은 `{{biz_company}}`, `{{biz_address}}` 치환자.
