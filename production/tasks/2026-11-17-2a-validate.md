# Codex 작업 지시문 — 2A. 문의 폼 검증 순수 함수와 단위 테스트

작성: 2026-11-17 / 작성자: 팀장(Claude Code)

## 목적
문의 폼 입력을 서버(Pages Function)와 브라우저가 **같은 규칙**으로 검증하도록, 의존성 없는 순수 함수 모듈과 단위 테스트를 만든다.

## 현재 상황
1단계 골격만 있다. `functions/lib/` 와 `tests/` 는 비어 있다. 검증 규칙은 `docs/design.md` 3절 "검증 규칙" 표가 기준이다.

## 프로젝트 위치
- 경로: 이 저장소 루트 (`package.json` 이 있는 곳)
- 브랜치: `work/new-site` (이미 체크아웃되어 있다. 배포 브랜치 `main` 에서 작업하지 않는다)

## 대상 파일
- 새로 만들기: `functions/lib/validate.js`, `tests/validate.test.mjs`
- 수정: `scripts/build-pages.mjs` — 맨 끝에 `functions/lib/validate.js` 를 `public/js/validate.js` 로 복사하는 3~5줄 추가 (브라우저가 같은 파일을 쓴다). 다른 부분은 바꾸지 않는다.

## 스택
ESM JavaScript. **외부 패키지 없음**. 브라우저와 Cloudflare Workers 런타임 양쪽에서 돌아야 하므로 Node 전용 API(`fs`, `process`, `Buffer`)를 쓰지 않는다. 테스트는 `node:test` + `node:assert/strict`.

## 만들 것 — `functions/lib/validate.js` 의 공개 API
```js
export const INQUIRY_TYPES = {
  "mobile-payment": "휴대폰결제 구입",
  "micro-payment": "소액결제 구입",
  "voucher-type": "상품권 종류 문의",
  "other": "기타",
};
export const LIMITS = { name: 30, messageMin: 10, messageMax: 1000, contactMax: 40 };

// 문자열 앞뒤 공백 제거 후 규칙 검사. 입력 객체의 값은 string | boolean | number | undefined 일 수 있다.
export function validateInquiry(input) {
  // 반환: { ok: boolean, errors: { [field]: "한국어 메시지" }, data: { type, name, contact, message, consent: true } }
  // ok 가 false 면 data 는 null. errors 는 실패한 항목만 담는다.
}
export function normalizeContact(raw)        // 휴대폰이면 숫자만 남긴 "01012345678", 카카오톡 ID 면 trim 한 원문, 둘 다 아니면 null
export function isMobilePhone(raw)           // 01 로 시작, 숫자 10~11자리. 하이픈·공백·점은 허용하고 제거해 판정
export function isKakaoId(raw)               // ^[A-Za-z0-9._-]{3,30}$
export function containsSensitiveNumber(text) // 주민등록번호 형태(숫자 6자리 + 선택적 하이픈 + 숫자 7자리) 또는 카드번호 형태(숫자 14~16자리 연속, 또는 4자리-4자리-4자리-4자리 하이픈·공백 구분) 가 있으면 true
export function isHoneypotTripped(input)     // input.website 가 비어 있지 않으면 true
export function parseConsent(value)          // true, "true", "on", "1", 1 → true. 그 외 false
```

## 규칙과 오류 메시지 (docs/design.md 와 같다. 메시지 문구를 바꾸지 않는다)
| 항목 | 규칙 | errors 키와 메시지 |
|---|---|---|
| type | `INQUIRY_TYPES` 의 키 중 하나 | `type`: 문의 유형을 선택해 주세요 |
| name | trim 후 1~30자 | `name`: 이름 또는 닉네임을 입력해 주세요 (30자 이내) |
| contact | trim 후 40자 이내이고 `isMobilePhone` 또는 `isKakaoId` | `contact`: 연락 가능한 휴대폰 번호나 카카오톡 ID 를 입력해 주세요 |
| message | trim 후 10~1000자 | `message`: 문의 내용을 10자 이상 입력해 주세요 (1000자 이내) |
| message 민감정보 | `containsSensitiveNumber(message)` 가 true 면 실패 (길이 검사를 통과한 뒤 검사) | `message`: 주민등록번호·카드번호·계좌번호는 적지 말아 주세요 |
| consent | `parseConsent` 가 true 가 아니면 실패 | `consent`: 개인정보 수집·이용에 동의해야 문의를 보낼 수 있습니다 |
`data.contact` 는 `normalizeContact` 결과, `data.name`·`data.message` 는 trim 한 값, `data.consent` 는 항상 `true`.
honeypot 은 `validateInquiry` 가 판단하지 않는다 (API 가 먼저 `isHoneypotTripped` 로 거른다).

## 테스트 — `tests/validate.test.mjs`
`node --test tests/` 로 돈다. 최소 아래를 각각 별도 `test()` 로 둔다.
- 정상 입력 → `ok: true`, `data` 가 정규화된 값, `errors` 가 빈 객체
- type 없음 / 목록에 없는 값 → `type` 오류
- name 빈 문자열 / 공백만 / 31자 → `name` 오류. 30자는 통과
- contact: `010-1234-5678`, `010 1234 5678`, `01012345678`, `0111234567`(10자리) 통과 → data.contact 는 숫자만. `02-123-4567`, `1234`, `홍길동` 실패. 카카오톡 ID `money_plan.1` 통과, `ab`(2자) 실패, 31자 실패
- message 9자 실패, 10자 통과, 1001자 실패, 1000자 통과
- message 에 `901231-1234567` 또는 `9012311234567` 또는 `1234-5678-9012-3456` 또는 `1234567890123456` 이 있으면 민감정보 오류. 휴대폰 번호 `010-1234-5678` 만 있는 문장은 통과
- consent: `true`, `"on"`, `"1"`, `1` 통과. `false`, `"off"`, `undefined`, `"yes"` 실패
- 여러 항목이 동시에 틀리면 errors 에 해당 키가 모두 담긴다
- `isHoneypotTripped({ website: "http://x" })` true, `{ website: "" }` 와 `{}` false
